# 实现设计说明

## 1. 为什么这么选技术

| 选项 | 结论 | 理由 |
| --- | --- | --- |
| React / Vue + 构建工具 | 否 | 评审需要 `clone` 下来就能跑；多一层 `npm install` 就多一个「跑不起来」的理由 |
| Python 后端 + 数据库 | 否 | 作业关注收藏、多联系方式、Excel 三个功能点，单机版用 `localStorage` 就能把交互做完整；后端会稀释前端的投入 |
| 原生 HTML/CSS/JS + localStorage | **采用** | 零依赖、双击即用、部署就是拷文件；改动只集中在四个 JS 文件里 |
| Excel 读写自己手写 xlsx | 否 | xlsx 本质是 zip + XML，手写容易在合并单元格、日期格式上踩坑；用 SheetJS 社区版成熟且能离线打包 |
| 表格用 CSV 代替 | 否 | 作业明确写了 Excel，且 CSV 表达不了「字段说明」第二个工作表、列宽、筛选等体验 |

数据的存储结构是一个带版本号的 JSON：

```json
{
  "version": 1,
  "savedAt": "2026-11-15T09:01:00.000Z",
  "contacts": [ { "id": "c_...", "name": "...", "methods": [ ... ] } ]
}
```

`version` 是为了以后加字段时能迁移；解析失败时会把原始字符串存到 `addressbook.v1.broken.<时间戳>`，再退回示例数据，避免用户打开就是白屏。

## 2. 分层结构

```text
index.html          页面骨架：侧栏 + 列表 + 两个 <dialog>
      │
app.js              渲染 / 筛选 / 弹窗 / 收藏 / 导入导出流程（只碰 DOM）
      │
      ├── store.js  localStorage 读写、示例数据、分组与标签统计
      ├── model.js  纯函数：类型表、规整、校验、判重指纹、排序、搜索文本
      └── excel.js  纯函数：宽表生成、表头识别、导入解析、三种合并策略
              │
              └── vendor/xlsx.full.min.js  （通过参数注入，方便 Node 测试）
```

依赖是单向的：`app.js → store/model/excel`，`excel.js → model.js`，`model.js` 不依赖任何人。
`excel.js` 不直接引用全局 `XLSX`，而是把 `XLSX` 作为第一个参数传进来——这样同一份代码在浏览器和 Node 测试里都能跑。

## 3. 数据模型

```text
Contact
├── id          string   前端生成的短 id（c_ + 时间 + 随机）
├── name        string   必填，≤ 40 字
├── company     string   公司 / 学院 / 部门
├── group       string   分组，空字符串视为「未分组」
├── tags        string[] 标签，最多 8 个，每个 ≤ 20 字
├── bookmarked  boolean  收藏
├── note        string   备注
├── methods     Method[] 联系方式，任意条（界面至少 1 条）
├── createdAt   ISO 时间
└── updatedAt   ISO 时间

Method
├── id       string
├── type     mobile | phone | email | wechat | qq | weibo | address | other
├── value    string   号码 / 账号 / 地址
├── label    string   备注，如「工作」「家庭」「总机转 8321」
└── primary  boolean  主要联系方式（全局唯一）
```

两个不变量由 `normalizeContact` 保证，任何入口（表单、导入、localStorage 回读）都会过一遍：

1. `methods` 里 `value` 为空白的项直接丢弃；
2. `primary` 最多一个，出现多个时保留最后一个被标记的。

## 4. 收藏功能

- 数据上就是一个布尔字段，切换时刷新 `updatedAt`。
- 交互上有三处入口，都改同一份数据：卡片右上角星标、「收藏」视图、编辑弹窗里的开关。
- 视觉上做了冗余编码，避免只靠颜色区分：金色左边框 + 金色填充星标 + 「已收藏」角标 + 左侧栏计数，色弱用户也能靠文字和边框判断。
- 列表重排策略：在「收藏」视图里取消收藏会立刻从列表消失；在「全部」视图里只就地更新卡片样式，不打断用户的浏览位置。

## 5. 多联系方式

- 编辑弹窗里是一组可增删的行（类型下拉 + 内容 + 备注 + 「设为主要」圆点 + 删除）。
- 最少保留一行，删最后一行时改成清空，避免出现「一个联系人一条联系方式都没有」的空状态。
- 展示层按类型给不同底色的图标（手机 / 座机 / 邮箱 / 微信-QQ / 地址 / 链接），一眼能分出是号码还是地址。
- 点击任一条联系方式直接复制到剪贴板：`navigator.clipboard` 不可用时退回 `document.execCommand('copy')`。
- 存储是数组而不是 `phone1/phone2/email1` 这种字段，所以「一个人两个手机号 + 三个邮箱 + 两个地址」不需要改表结构。

## 6. Excel 导出

导出流程：`筛选后的列表 → buildTable() → aoa_to_sheet → 列宽/筛选 → 两个工作表 → XLSX.write → Blob 下载`。

宽表结构（`maxMethods = max(3, 最多联系方式数)`）：

| 姓名 | 公司/部门 | 分组 | 标签 | 收藏 | 备注 | 联系方式1类型 | 联系方式1号码 | 联系方式1备注 | … | 联系方式N备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

几个细节：

- **一个联系人严格一行**，满足了「each contact should occupy a separate row」；同时「每种信息一列」也满足，因为号码列是带类型的。
- 至少留 3 组联系方式列，这样导出的空文件可以直接拿去手填。
- 第二个工作表「字段说明」写清每个字段的含义、示例、以及「联系方式可以继续向右扩展」的说明，导出的文件自己就是文档。
- 列宽按字段设置，`!autofilter` 加了表头筛选，`字段说明` 表三列宽 18/62/32。
- 导出的是**当前筛选结果**，Toast 里会写明「当前筛选结果」还是「全部联系人」，避免用户以为导漏了。

## 7. Excel 导入

导入比导出难，因为它要接受「别人的表格」。流程：

```text
File → FileReader（xlsx 用 ArrayBuffer，csv 用文本）
     → XLSX.read
     → pickSheet：优先「联系人」，否则第一个能识别出表头的表
     → findHeaderRow：前 10 行里命中已知字段最多的一行（跳过标题行、空行）
     → classifyHeader：每列归类为 基础字段 / 联系方式分槽 / 某种联系方式类型 / 未知
     → 逐行构造 Contact（跳过全空行，缺姓名记无效行）
     → mergeContacts：与现有数据按名字合并，返回每行处理结果
     → 预览 → 用户确认 → replaceAll + 保存
```

### 7.1 表头识别

表头文字先归一化（去空格、下划线、连字符，转小写）再匹配，所以 `E-mail`、`邮箱`、`邮箱地址` 都归到 email。三类规则按顺序匹配：

1. **基础字段别名**：`姓名/名字/name`、`公司/单位/department`、`分组/分类/group`、`标签/tags`、`收藏/星标/bookmark`、`备注/note`。
2. **分槽格式**：正则 `^联系方式(\d+)(类型|号码|内容|值|备注|标签)$`，英文 `contact1type` 也认。
3. **直接是类型名**：`手机`、`手机号`、`Phone`、`邮箱`、`微信`、`地址` → 该列整体当成一条该类型的联系方式。

只有第 3 类兜底不算「未知列」；未知列（比如「序号」）会被忽略，不影响导入。

### 7.2 脏数据处理

| 情况 | 处理 |
| --- | --- |
| 文件名不对（.txt） | 直接提示，不读文件 |
| 表里没有「姓名」列 | 中止并提示「缺少姓名列」 |
| 某行没有姓名 | 记为无效行，跳过，预览里标红 |
| 同一文件里重名 | 合并成一条：联系方式取并集，标签取并集 |
| 空的邮箱 / 电话单元格 | 直接不生成该条联系方式 |
| 收藏列写「Y」「1」「✓」 | 都认成已收藏 |
| 标签一格写多个 | 逗号 / 分号 / 顿号 / 竖线都能分隔 |
| 超过 6 位小数的时间、公式 | `sheet_to_json` 取显示值，不解析公式 |

### 7.3 三种重复策略

| 策略 | 联系方式 | 标签 | 公司/分组/备注 | 收藏 | id |
| --- | --- | --- | --- | --- | --- |
| 合并（默认） | 并集，重复的（类型+号码）不重复添加 | 并集 | 原值为空才用新的补 | 或运算 | 保留原 id |
| 跳过 | 不动 | 不动 | 不动 | 不动 | — |
| 覆盖 | 用新的整体替换 | 替换 | 替换 | 替换 | 保留原 id 与创建时间 |

判重键是**归一化后的姓名**（去空格、大小写），所以「张鑫宇」和「 张鑫宇 」算同一个人；而「两个不同的张伟」在导入时会被合并，这是刻意的取舍——通讯录场景重名合并比重复条目更可接受，且用户可切到「跳过」。

## 8. 界面设计

- 布局：左侧固定导航（全部 / 收藏 / 分组 / 标签），右侧内容区；卡片自适应列（`minmax(296px, 1fr)`），窄屏自动单列。
- 状态提示：所有异步或不可逆操作都走 Toast（删除是可撤销的 Toast），不使用 `alert` / `confirm`，避免打断截图和演示。
- 空状态分了两种：「还没有联系人」和「没有符合条件的联系人」，后者会提示清除筛选。
- 可访问性：星标是 `<button aria-pressed>`，弹窗用原生 `<dialog>`（自带焦点陷阱和 Esc 关闭），输入框都有 `label`。
- 键盘：`Ctrl + K` 聚焦搜索，`Esc` 关弹窗。

## 9. 测试与验证方式

- 纯函数（model / excel）用 Node 直接测，10 + 10 个用例，见 `tests/`、`docs/test-report.md`。
- 界面用无头 Edge + DevTools 协议跑真实交互并截图（`_verification/capture_addressbook.py`），
  导出的文件再用 openpyxl 打开校验工作表名、行列数与内容。
- 演示视频由同样的真实交互逐帧录制后合成（`_verification/record_demo.py`）。

## 10. 取舍与不足

1. **没有后端**：两人协作时无法共享数据；如果需要，下一步是把 `store.js` 的读写换成 `fetch('/api/contacts')`，`model.js`/`excel.js` 不用动。
2. **判重只看姓名**：同名不同人会被合并，已通过「跳过 / 覆盖」策略和预览让用户兜底。
3. **联系方式类型固定枚举**：用户想加「钉钉」「Telegram」只能选「其他」。真要做成产品应该允许自定义类型并存进 `localStorage`。
4. **表格样式有限**：SheetJS 社区版不写单元格样式，所以导出的表头没有加粗填色，只做了列宽和筛选。想更漂亮要换 `xlsx-js-style`，但那会让仓库多一个依赖，作业里没必要。
